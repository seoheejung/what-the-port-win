# What the Port for Windows · 구현 기획

## 목표
노트북에 남은 개발 서버를 시스템 트레이에서 확인하고, 자원 사용 원인을 파악하고, 필요한 서버만 정리한다. Tomjohn Design의 WhatThePort를 Windows 네이티브 앱으로 이식한다. 원본 ZIP은 보존하며 MIT 저작권과 Geist 폰트 라이선스를 배포물에 포함한다.

## 기술 선택
- Windows 10/11 x64 / .NET Framework 4.8 / C# / WPF. 설치된 Framework 컴파일러로 오프라인 빌드한다.
- Win32 `GetExtendedTcpTable`로 IPv4/IPv6 TCP 리스너와 연결을 조회한다. Toolhelp로 부모·자식 관계를 만든다.
- 프로세스의 시작 시각, working set, CPU 누적 시간을 샘플링한다. 실제 CPU는 논리 코어 수로 정규화한다.
- 현재 폴더는 접근 가능한 동일 사용자 프로세스의 PEB에서 해당 필드만 읽고, Git 브랜치는 `.git/HEAD`로 확인한다. 실패 시 프로세스 이름으로 표시한다.
- UI 스레드와 스캔을 분리한다. 3초 기본 주기, 최근 10분의 제한된 메모리 기록, PID별 중복 집계 방지.
- 설정과 명시적 세션/미리보기 링크는 `%LOCALAPPDATA%/WhatThePort`의 JSON에 저장한다. 테스트/데모는 별도 저장 경로를 사용한다.

## 화면
1. Servers: 전체 메모리, 서버/다른 앱/여유 메모리 바, CPU, 포트별 이름·브랜치·실행 시간·스파크라인.
2. Detail: 포트, 가동 시간, 프로젝트·에이전트·브랜치·폴더, 10분 메모리/CPU 차트, 프로세스 목록, 로컬 URL·터미널·세션·미리보기·종료.
3. Clean up: 후보 사전 선택, 예상 회수 working set, 보호 표시, 최종 선택 종료.
4. Settings: 샘플 주기, 메모리/성장/CPU 경고, idle 시간, Off/Ask/Automatic, 터미널, 알림.
5. Link: 프로젝트/포트별 Codex 또는 Claude Code 세션 ID, Vercel HTTPS URL 등록.

## 안전한 종료와 자동 정리
- 사용자가 선택한 서버와 그 서버 소유 하위 프로세스만 종료한다. 부모 셸·에이전트에는 올라가지 않는다.
- 다른 리스너의 하위 트리를 제외한다. 같은 PID의 여러 포트는 하나의 서비스로 묶는다.
- 같은 핸들로 생성 시각, 사용자 SID, 세션을 검사한 뒤 종료한다. 오래된 스냅샷이나 PID 재사용은 실패 처리한다.
- PostgreSQL, Redis, MongoDB, MySQL, SQL Server 등은 보호한다. 앱 자신의 프로세스와 조상도 보호한다.
- 자동 정리는 Off 기본. 관측상 연결 없음·낮은 CPU가 설정 시간 지속되고, 일정 시간 이상 관측된 서버만 대상이다. 메모리/CPU 경고 서버는 자동 종료하지 않는다.
- Windows의 일반 콘솔 프로세스는 SIGTERM을 지원하지 않으므로, 종료는 명시적인 프로세스 종료다. 화면에서 종료 영향을 안내한다.

## 에이전트·Vercel 연결
- 부모 프로세스 이름으로 Codex/Claude의 연관성을 표시할 수 있다. 정확한 세션 ID는 UI 또는 `wtp link`로 등록한다.
- `codex resume <id>` / `claude --resume <id>`를 선택한 PowerShell 또는 Windows Terminal에서 실행한다.
- Vercel API 인증/배포 없이 등록된 `*.vercel.app` HTTPS 주소를 연다. 정확한 세션·배포를 추정하지 않는다.
- 단축키: Ctrl+Alt+P 트레이 패널, Esc 뒤로/숨김, Ctrl+, 설정, Enter 상세, O 로컬 URL, T 터미널, A 세션, V 미리보기, C 정리.

## 검증 완료 조건
- 빌드가 네트워크/패키지 설치 없이 성공한다.
- 정책 테스트: PID 재사용, 보호 프로세스, 부모 경계, 다른 서비스 제외, idle, 경고, 이력 제한, URL/세션 검증.
- 통합 테스트: 자체 테스트 TCP 프로세스 탐지, IPv4/IPv6, 자원 표본, 연결 수, 종료 후 리스너 제거, 다른 프로세스 보존.
- WPF 스냅샷: 목록, 상세, 정리, 설정, 빈 화면을 생성·검토한다.
- CLI JSON 결과, 설정 저장/복구, 종료 코드 확인.
- 실제 배포/서명/자동 업데이트는 포함하지 않는다. WSL/Docker 내부 PID·리소스, 다른 사용자/관리자 프로세스의 상세 정보는 범위 밖이다.

## 진행 결과 · 2026-10-05
- 완료: 추가 패키지 없는 x64 네이티브 빌드, 트레이, 전역 단축키, IPv4/IPv6 탐지, 프로세스 트리 자원 집계, Git 폴더 정보, 10분 차트, 경고, 정리, 자동 정리 정책, 터미널/세션/미리보기 링크, JSON CLI.
- 완료: 요청한 기획·규칙·디자인·README, 원본 MIT/폰트 OFL 보존, 포터블 실행·선택적 설치·패키징 스크립트.
- 검증: Core/실제 프로세스 통합 71개, WPF UI 19개, CLI 2개 통과. 실앱 트레이·윈도우 핸들·전역 단축키 등록·실시간 네이티브 스캔 확인.
- 실제 테스트 서버 2개를 생성해 IPv4/IPv6, 연결 수, PID 재사용 방어, 선택 종료·비선택 유지·포트 해제를 확인했다. 테스트가 만든 프로세스 외에는 종료하지 않았다.
- 5회 네이티브 스캔은 이 환경에서 약 53ms였다. 일반적인 성능 보장 수치는 아니다.
- 목록, 상세, 정리, 설정, 링크, 빈 상태의 스냅샷 6개를 생성했다. 원본의 포트 색·간결한 행·메모리 바·차트·정리 확인 흐름을 유지했다.
- 추가 동작 검증 결과는 `.project/verification.md`에 기록한다.

### 명시적인 범위 차이
- 정확한 Codex/Claude 세션 및 Vercel URL은 수동 등록한다. 대화/인증 파일이나 Vercel API를 조회하지 않는다.
- 지원 터미널은 PowerShell과 Windows Terminal이다. WSL/Docker 내부, UDP, 다른 사용자 프로세스, 원본의 재시작·자동 업데이트는 포함하지 않는다.
- 서명/배포/시작 메뉴 설치/로그인 시작 등록은 실행하지 않았다. 필요한 로컬 스크립트와 포터블 ZIP을 제공한다.
